# Kast v0.1 — Design

Werktitel: **Kast.** Datum: 2026-05-12. Status: design, nog niet geïmplementeerd.

## 1. Doel van v0.1

Toets in een paar weken werk of het kern-idee — *"AI geeft outfit-advies uit eigen kast op basis van een anchor-item"* — daadwerkelijk waarde levert voor de eerste eindgebruiker. Slaagt v0.1 niet, dan vervalt het hele product zonder dat we 10 fasen aan infra hebben gebouwd.

**Wat v0.1 niét is:** een gepolijst product. Het is een gerichte test van één hypothese met één gebruiker, met de ontwikkelaar er fysiek naast.

## 2. Doelgebruiker en context

- **Simone** (~48, partner van de ontwikkelaar). iPhone-gebruiker. Werkt in IT/finance, gefascineerd door AI, wil mee-experimenteren. Heeft het idee zelf geformuleerd: *"Ik heb een topje, wat past hierbij uit mijn kast en eventueel wat moet ik erbij kopen."*
- Geen Juul, geen huishouden-feature in v0.1.
- Apple Dev-account is géén v0.1-blokker: v0.1 draait op de Pixel 8 Pro van de ontwikkelaar, met Simone ernaast aan tafel. iOS-deployment is een v0.2-issue.

## 3. Kern-use case

**Anchor-item-flow.** Simone wijst één item aan dat ze wil dragen → de app produceert **één complete outfit + tekstuele uitleg** waarom die outfit werkt.

Geen dagelijkse prompt, geen "wat doe ik vandaag aan." Het is incidenteel gebruik: zij twijfelt over een item, ze vraagt advies, ze krijgt één voorstel.

## 4. Outfit-definitie

Een outfit in v0.1 = **4 slots**:

1. Top
2. Broek of rok
3. Schoenen
4. Jas of jasje

**Géén accessoires** in v0.1 (sjaal, tas, sieraden, riem). Komt mogelijk in latere versies.

Het anchor-item kan in principe in elk van deze 4 slots zitten. Als Simone een broek aanwijst, vult de AI de andere drie. (v0.1-keuze; we beginnen pragmatisch met "any-slot-anchor" en kijken na gebruik of beperken nodig is.)

## 5. Kast-setup

**Eenmalige sessie, ~45–60 min, ontwikkelaar + Simone samen aan tafel.**

- Tot 30 items in haar kast, beginnend met meest-gedragen kleding. Spreiding over de 4 outfit-slots (geen lege categorie).
- Per item handmatig:
  - 1 foto (door Simone op haar manier — géén Vision-classificatie *tijdens setup*; de advies-call gebruikt Vision wél, zie §8)
  - 3 velden: categorie (top/broek/rok/schoenen/jas), kleur(en), gelegenheid (casual/werk/uit/sport).
- Eén vrij tekstveld voor lichaamsproporties en stijl-voorkeuren. Simone vult zelf in haar eigen woorden ("korte benen, iets dikkere benen, ik draag liever geen [...]"). Die tekst gaat letterlijk de prompt in als context.

**Géén** maten via meetlint, géén body-shape-extractie uit foto, géén stijl-quiz, géén budget/winkelvoorkeuren, géén locatie/geboortejaar.

## 6. Style reference photos

Naast de 30 items kan Simone **0–5 foto's** toevoegen van outfits die ze in het verleden droeg en goed vond.

Deze foto's zijn **prompt-context, geen catalogus.** Bij elke advies-vraag stuurt de Edge Function deze foto's mee naar de Claude API met de instructie *"dit zijn outfits die Simone draagt en goed vindt — gebruik dit als stijl-referentie."* De AI extraheert er geen items uit, classificeert ze niet, dedupliceert ze niet.

Optioneel veld; v0.1 functioneert ook met 0 referentie-foto's.

## 7. Feedback en evals

**v0.1 feedback:** korte vrije tekst per advies. Geen sterren, geen knoppen, geen instrumentatie.

**v0.1 evals:** kwalitatief, mondeling, aan tafel tussen ontwikkelaar en Simone. Vragen die we willen kunnen beantwoorden:

- Heeft Simone de geadviseerde outfit ooit gedragen?
- Begrijpt ze de uitleg?
- Verrast ze het advies, of voelt het flauw?
- Wanneer pakt ze de app uit zichzelf erbij? Wanneer juist niet?

Geïnstrumenteerde evals (saved outfits, "echt gedragen"-log, retentie-metrics, sterren-feedback) zijn een v0.2-onderwerp, gekoppeld aan de komst van Juul als consumer-gebruiker zonder dagelijkse face-time.

## 8. Architectuur

### Stack

- **Frontend:** React Native met Expo. Eén codebase Android + iOS. v0.1 draait alleen op Android (Pixel) maar de codebase ondersteunt iOS zodra Apple Dev geregeld is.
- **Backend:** Supabase. Postgres + Auth (Google) + Storage.
- **AI:** Claude API via een Supabase Edge Function. API-key zit nooit in de app.

### Datamodel (5 tabellen)

- `auth.users` — Supabase managed
- `clothing_items` — owner_id, categorie, kleur(en), gelegenheid, vrij-tekst notities
- `clothing_photos` — item_id, storage path, type (item / style_reference)
- `advice_requests` — owner_id, anchor_item_id, timestamp, prompt-payload-snapshot
- `advice_responses` — request_id, outfit (referenties naar de 3 niet-anchor items die samen met het anchor de complete outfit van 4 slots vormen), uitleg-tekst, feedback-tekst (vrij)

**Niet in v0.1:** `households`, `household_members`, `profiles`, gestructureerde `advice_feedback`. Komen er als migratie bij in v0.2 — niet als rebuild.

### Edge Function

- Eén endpoint: `POST /advise`
- Input: `anchor_item_id`
- Function:
  1. Haalt kast (clothing_items + photos) op voor de user.
  2. Haalt style_reference_photos op (max 5).
  3. Bouwt de Claude-prompt: kast + proporties-tekst + style-references + anchor-item + outfit-definitie (4 slots).
  4. Roept Claude API aan, parseert response.
  5. Slaat `advice_responses` op, geeft uitleg + 3 item-IDs terug aan app.

### Tests + code review

- Tests + code review vanaf commit 1. Geldt voor zowel app-code, Edge Function als migrations.
- Minimaal: unit-tests voor prompt-bouwer en Edge Function response-parser. Integratie-test voor end-to-end advies-flow met gemockte Claude-response.

## 9. Infra-risico-mitigatie: parallel prompt-prototype

Infra-setup kost ~10–12 uur voordat product-code begint. Risico: als het kern-advies geen waarde levert, is die tijd verloren.

**Mitigatie:** bouw het prompt-prototype parallel aan de infra. Een notebook of klein script met:

- Hardcoded dummy-kast (5–10 items als JSON met fake foto-URLs).
- Hardcoded proporties-tekst en 1–2 dummy style-reference-foto's.
- Directe Claude API call.

Doel: prompt-iteraties doorlopen totdat de output kwalitatief goed genoeg is, *voordat* alle Supabase-infra af is. Zodra prompt overtuigend is, weten we dat de infra het bouwen waard is.

## 10. Wat expliciet NIET in v0.1 zit

- Juul. Geen tweede gebruiker.
- Huishouden / gedeelde kast / RLS voor multi-user.
- Bijkoop-advies (Simone's "eventueel" — komt in v0.3).
- Sterren-feedback en instrumentatie-evals.
- Vision-classificatie van items tijdens setup.
- Body-shape extractie uit foto.
- Stijl-quiz, budget-vragen, winkelvoorkeuren, geboortejaar, locatie.
- Seizoen/weer-integratie.
- "Outfit voor gelegenheid" (gala-modus).
- Echte productlinks bij bijkoop.
- iOS-deployment, App Store/TestFlight.
- "Geef me een andere outfit"-retry-knop. (Open punt — zie §12.)
- Auto-extractie van items uit een foto-bibliotheek. (Goed idee, maar v3.0+.)

## 11. Sequencing-context (richtinggevend, geen commitment)

Wat hierna komt — elk eigen brainstorm wanneer het tijd is:

- **v0.2:** Juul + huishouden + eval-instrumentatie + Apple Dev-account / TestFlight.
- **v0.3:** Bijkoop-advies, tekstueel.
- **v0.4:** Seizoen/weer-integratie. Body shape iets gestructureerder als nodig.
- **v0.5:** "Outfit voor gelegenheid" (gala-modus), agentic patterns, evt. productlinks.

## 12. Bewust open punten voor het implementatieplan

Deze worden in het volgende stadium (writing-plans) beslist, niet in dit design:

1. **Retry-knop ("andere outfit")** ja/nee voor v0.1.
2. Concrete keuze tussen Haiku en Sonnet voor de advies-call (kosten vs. kwaliteit). Prompt caching ja/nee. Structured outputs ja/nee.
3. Hoe foto-storage in Supabase precies wordt georganiseerd (één bucket, mapstructuur, signed URLs).
4. UI-detail van het advies-scherm: hoe worden 3 items naast elkaar getoond, hoe staat de uitleg eronder/erboven, hoe ziet het feedback-veld eruit.
5. Definitie-van-Done per feature voor het implementatieplan.
6. Of v0.1 in een git-repository (incl. `git init`) of zonder versie-controle begint — zwaar aan te raden om vanaf commit 1 te versie-controleren, ook voor een hobby-project.

## 13. Definition of Done voor v0.1

v0.1 is "klaar genoeg om Simone er een week mee te laten experimenteren" als:

- Simone kan inloggen met Google.
- Simone heeft 30 items in haar kast met foto + 3 velden, plus haar proporties-tekstveld ingevuld.
- Simone kan optioneel 1–5 style reference photos toevoegen.
- Simone kan een anchor-item aanwijzen en binnen ~10 seconden een advies met uitleg ontvangen.
- Simone kan per advies een vrije reactie achterlaten.
- De ontwikkelaar kan in Supabase zien welke adviezen zijn gegeven en welke reacties zijn gegeven.
- Tests draaien groen in CI; code review-proces actief.
